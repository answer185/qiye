# 前端工程化思考

## 如何理解前端工程化

前端工程化本质上是将前端开发从“个人编码行为”升级为“可规模化协作的工程系统”。

它的核心不是工具，而是控制复杂度，让系统在团队扩大和业务增长的情况下依然可维护、可演进。
可以从以下3个方面来理解：
### 技术层
解决浏览器无法直接运行源码的问题：
- 模块化
- 构建工具
- 代码转换（TS / JSX）
- 依赖管理
- 性能优化（tree-shaking / code splitting）
这是“运行时工程”。

### 结构层
解决代码规模扩大后的复杂度问题：
- 模块边界设计
- 目录结构策略
- 组件分层
- 依赖方向控制
这是“复杂度管理”。

###  协作层
解决多人协作效率问题：
- 代码规范
- Git 流程
- CI/CD
- 自动化测试
- 发布策略
这是“组织效率”。

## 与其他软件工程化有什么不同
其他类型项目的工程化，目的是相同听，都是控制复杂度。但是复杂度的类型不同。

前端复杂度主要来自：
- UI 状态爆炸
- 浏览器环境差异
- 构建系统
- 性能优化
- 组件依赖
- 交互细节

前端工程化主要控制的是：协作复杂度 + 构建复杂度 + 状态复杂度

后端复杂度来自：
- 并发
- 数据一致性
- 分布式系统
- 网络调用
- 数据库事务
- 容错

后端工程化控制的是： 数据复杂度 + 系统稳定性复杂度 + 运维复杂度

## 前端工程化主要解决的问题
从复杂度的角度来看：

技术复杂度，如：
- 浏览器兼容
- 依赖管理
- 性能优化

代码复杂度，如：
- 模块耦合
- 重复代码
- 边界不清晰

协作复杂度，如：
- 技术债累积
- 重构风险大
- 新人难上手

## 中大型项目，从哪些方面去做工程化建设
在中大型 React 项目中，工程化建设不是简单地引入工具，而是从构建体系、代码结构、协作流程和系统演进四个维度建立一套控制复杂度的机制。
### 构建与运行时工程
- 选型（Vite / Webpack）
- 构建优化（缓存、增量构建）
- 代码分割策略
- 资源加载策略
目标是：提高开发反馈速度和生产性能。

### 代码组织工程
- 采用 feature-based 目录结构
- 明确模块边界
- 组件分层（UI / 业务 / 容器）
- 统一状态管理策略
目标是：控制代码的复杂度

### 协作与质量工程
- ESLint + Prettier
- TypeScript 严格模式
- Git 分支策略
- CI/CD 自动化
- 单测 + E2E
目标是：降低协作摩擦和发布风险。

### 演进与治理工程
- 技术债管理
- 渐进式重构
- 依赖可视化分析
- 文档体系建设
目标是：保证系统的可持续发展

工程化的终极目标不是效率本身，而是在团队规模扩大和业务增长的情况下，系统依然可预测、可维护、可扩展。

## 运行多年的项目出现问题如何调查和解决
一个持续迭代多年的项目，经常会出现以下问题：
- 构建时间变长
- 本地启动越来越慢
- 打包后体积变大
- 某些页面首屏明显变慢

前3个问题虽然根因是因为项目不断迭代，代码量增加引起，但是根本原因还是在构建和运行时工程已经跟不上了，需要做相应的优化。可以做的优化通常有：
- tree-shaking打开。
- 拆分chunk
- 按页面拆分代码
- 拆分vendor等公共库
- 做预构建和缓存等。

对于页面的首屏加载变慢，就需要针对：
- 资源加载过程
- JS运行
- 渲染
- 数据请求
这4个方面进行分析和优化。

## 为什么要有构建工具？
浏览器天然存在几个问题：
1. 不支持 TypeScript
2. 不支持 JSX
3. 旧浏览器不支持新语法（ES6+）
4. 不能直接处理 SCSS / Less
5. 不能理解 import 第三方 npm 包的解析规则
6. HTTP 1.1 下多文件加载性能差
所以我们写的代码：
```js
import React from 'react'
import styles from './index.module.scss'
```
浏览器是无法直接运行的。

构建工具做的事情其实就三步：
> 解析依赖 → 构建依赖图 → 输出浏览器可执行资源

## webpack与vite的本质区别
Webpack 思路（传统 bundler）
- 入口文件开始
- 构建完整依赖图
- 打成一个或多个 bundle
- dev 时也需要打包
问题：
- 项目大时，启动慢
- 热更新慢

Vite 思路（现代构建）：

dev 阶段：
- 利用浏览器原生 ESM
- 不提前打包
- 只在请求时按需编译
build 阶段：
- 使用 Rollup 进行打包
- 做 tree-shaking
- 做 chunk splitting
