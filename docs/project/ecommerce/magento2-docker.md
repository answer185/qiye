# 基于Magento2+Docker的规模化建站方案

## 背景
客户的团队需要做基于独立站的去测品。在成功找到合适的产品前，需要建设很多的站来测试不同的品类、国家或区域。因为有广告投放操作，所以就算在测试阶段也需要保证性能。
每个站点的 SKU 数量不会太多，但需要保证：
- 架构稳定
- 部署快速
- 可长期维护
- 易于扩展拆分

## 预期目标
新建一个站的时间成本控制在3个小时左右，并实现以下效果：
1. 维护好基础项目，这些项目是基于模板或品类的。
2. 新功能特性都在基础项目中开发，最好在一个base项目中开发，再同步到各个模板或品类的基础项目。
3. 线上的产品站只维护数据，更新新功能只需要git pull拉取新代码。
4. 新站点只需求克隆下相应的项目代码、新建数据库、并修改或新建一个配置文件，设置好相应的数据库连接和域名信息即可。
5. 建立数据中心，从数据中心中导出可以与站点对接的数据导入格式。直接导入即可。

## 技术选型
### 电商系统
主要考虑：
- shopify
- wordpress+woocommerce
- magento2
最终的选择是Magento2，其原因是：
- shopify每建立一个站，都需要去配置模板等，且站多之后，成本很高。毕竟按站收月租及按单抽成。
- wordpress+woocommerce也是一个很好的选择，但是后台管理界面、性能、安全性等和Magento2差距还是很大。毕竟不是专门的电商平台。
- Magento2维护成本高，上手难度大，但是对我们来说这个不是问题。从长远看它更稳定且扩展性更好。

### 模板
不自己开发，直接购买。

### 基础项目
前期核心的项目是magento-base-template，固化magento的版本，并整合一个模板，初始化电商相关的协议文章。执行：
```sh
php bin/magento app:config:dump
mysqldump base_db > base.sql
```
把配置文件化及基础的数据库文件。这样在新建站点时，只需要导入数据库和创建或修改app/etc/env.php，并做相应的修改。
再执行：
```sh
php bin/magento app:config:import
```
可以节省掉setup:install命令的执行时间。

### 服务器空间及运行环境
- 基于docker保证本地开发环境和服务器一致。
- 测试期间，服务器空间使用8G内存以上的VPS，站点流量起来后，再根据流量预期做迁移及优化配置。
- 服务器系统：Ubuntu。

### 数据中心
- 基于Electron开发桌面端工具，供员工采集需要的单品。
- 数据在局域网服务器上。
- 有个Web后台，可以做数据清洗、组合和导出等管理操作。
- 内置采集规则，可以根据需要，针对特定站点增加规则。

## 新站上线流程
- git clone 相应的项目代码
- composer install 安装相应的依赖
- 创建数据库，并导入base.sql
- 创建或修改app/etc/env.php
- 执行：php bin/magento app:config:import
- 图片上传及相关数据导入
- 其他修改：如服务协议，配送等之类的文章。

## 站点更新流程
- 功能更新：使用git pull 拉取新代码。
- 数据更新：在后台维护或再导入。

## 多站维护方案
- 建立服务器清单
- 建立域名清单
- 命名规范：根据域名、品类等做相关命名
- 部署规范：封装成deploy.sh，一键部署。
- 备份：自动备份及下载。
- 服务器性能监控
- 基于Google analytics做流量分析
