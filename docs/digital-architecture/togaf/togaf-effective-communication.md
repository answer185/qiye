# TOGAF-如何高效交流
## 背景
内部交流是IT负责人/制造业架构师的重要工作内容，在这个过程中不能只是列一个简单的提问清单，需要有一定的框架，以更好地理解业务内容。

> 人 → 事 → 流程 → 系统 → 数据 → 问题 → 指标 → 决策

以工厂常见的生产计划变更，导致车间忙乱、交期延误的例子为例来说明。

## 交流过程
### 聊人
第一步不是先聊系统，而是先了解生产计划这件事，是由哪些人参与的，比如：
- 架构师: “我先不聊系统，我想先了解一下生产计划这件事情，平时主要有哪些人参与？”
- 生产经理: “主要是计划员、生产经理，还有各车间主管。业务那边也会参与，因为他们经常会插单。”
- 架构师：“那最终谁对生产计划负责？”
- 生产经理：“计划员负责做，但生产经理最后审核。”

可以获得至少有四类角色： 业务、计划、生产经理、车间主管

### 聊事
确定在生产计划制定的过程中，经历了哪些事，模拟过程：

你：
- “那我们具体说一张订单。比如今天接到一个客户订单，从订单进来到最终安排生产，中间大概发生什么？”
生产经理：
- “业务接单以后，把订单给计划员，计划员根据交期、库存、产能这些东西安排生产。”
你：
- “然后呢？”

生产经理：
- “排完以后发给车间，车间按照计划生产。”

你：
- “计划制定以后，最容易发生什么变化？”

生产经理：
- “变化很多啊。”

你：
- “比如？”

生产经理：
- “客户突然要提前交货，业务会催。然后有时候材料没到，有时候机器坏了，还有就是突然插单。”
这时候你已经开始看到真正的业务了。
### 聊流程
将上面的事情拼成相应的流程，并重新确定，可以手动画一个简单的图，如：
```
客户订单
   ↓
业务确认
   ↓
计划员排产
   ↓
生产经理审核
   ↓
车间执行
   ↓
生产完成
```

模拟聊天过程：

你：
- “如果发生插单呢？”

生产经理：
- “业务直接找计划员。”

你：
“计划员重新排？”

生产经理：
- “对。”

你：
- “需要生产经理重新审批吗？”

生产经理：
- “一般不用，比较急的时候计划员直接调整。”

这里非常关键。

你发现：
- 系统里可能存在一个“正式流程”，但现场真正运行的是另外一套流程。

继续问：
- “那如果计划已经发给车间了，后来又调整，车间怎么知道？”

生产经理：
- “计划员微信群里通知。”

你：
- “系统里面会同步吗？”

生产经理：
- “有时候会，有时候计划员懒得改。”
这个时候，问题开始浮出来了。

### 聊系统
在弄懂事和流程后，才进入系统，了解用户在哪里做生产计划，看哪些数据，有什么问题等。

### 聊数据
弄懂用户在做生产计划时，主要看哪些数据。比如：
- 订单交期
- 库存
- 材料到货
- 机器产能
- 人员

还有他们的数据怎么看的。从哪看。有些数据可能要问过现场的人员后才知道，即：
> 数据没有形成闭环。

### 聊问题
让用户自己开始说问题。还有产生的影响。与上面的内容对照，即可得出相应的问题链条，比如：
```
客户插单
材料异常
设备异常
     ↓
生产计划频繁调整
     ↓
计划与现场不同步
     ↓
车间执行混乱
     ↓
生产效率下降
     ↓
订单延期
```

### 聊指标
问用户有没有统计过相关的指标，比如 延期率、延期的原因及占比。

可以得到一个相关的指标树：
```
订单延期 15%
│
├── 材料问题 40%
├── 计划调整 30%
├── 设备问题 20%
└── 其他     10%
```

还会发现，用户可能只有结果指标，没有足够的过程指标。

### 聊决策
即理解用户在遇到异常流程时，现在是怎么做决策的。比如来了一个紧急订单，怎么决定要不要插入？

生产经理可能会告诉你：他需要看下现有的计划、交期、还有现在的生产到哪了，再看有没有空余产能之类。

还有理解这些数据他们现在能不能从系统上直接看到。

## 总结
先找人，再理解事；再还原流程；再看系统；再追数据；最后找问题、指标和决策。
