# 制造业灾备架构设计：从数据备份到业务连续性

## 背景
在制造企业中，ERP、MES、WMS、PLM 等信息化系统已经逐渐成为生产经营的重要基础设施。这些系统一旦发生故障，影响的往往不只是“IT 系统不能用了”。可能出现的是：
- 销售无法接单
- 生产计划无法下达
- 车间无法报工
- 海外工厂无法正常协同
等情况。

因此，对于制造企业来说，灾备真正要解决的问题并不是：
> “我的数据有没有备份？”
而是：
> “如果 IT 系统发生严重故障，企业还能不能继续经营？多久能够恢复？”

## 什么是灾备
### 定义
灾备，全称是“灾难恢复”
> Disaster Recovery
简称DR。

灾备就是在 IT 系统发生重大故障甚至整个生产环境不可用时，能够通过预先设计好的机制恢复系统和数据，让业务尽可能继续运行。

### 灾备 ≠ 数据备份
备份只是灾备体系中的一个组成部分。可以简单理解为：
```
                 业务连续性
                     │
             ┌───────┴───────┐
             │               │
          灾难恢复          应急运营
             │               │
      ┌──────┼──────┐        │
      │      │      │        │
    数据    系统    基础设施   人员/流程
    备份    恢复    恢复       /应急机制
```

## 常见场景
### 数据库故障
例如：
- 数据库损坏
- 磁盘损坏
- 数据库误删除
- SQL 操作错误
- 数据库服务器宕机

### 服务器故障
例如：
- 主机硬件损坏
- 操作系统故障
- 虚拟化平台故障
- 应用服务器宕机


### 存储故障
如果企业所有业务系统的数据都集中在一个存储设备上，那么存储本身就可能成为单点故障。

例如：
```
ERP
MES
WMS
   │
   ↓
共享存储
   │
   ↓
存储故障
   │
   ↓
多个系统同时受到影响
```

### 网络故障
制造企业越来越依赖网络。

因此灾备也应该考虑：
- 核心交换机
- 防火墙
- Internet 出口
- 专线
- VPN
- SD-WAN
- 无线网络
等基础设施。

### 机房灾难
例如：
- 火灾
- 洪水
- 地震
- 长时间停电
- 空调系统故障
- 机房设备整体损坏

这时如果所有服务器和备份都放在同一个机房，那实际上并不能解决问题。

### 勒索病毒
这是网络安全事件，入侵者可能把所有线上的数据加密。这里就需要考虑：

离线备份、不可变备份、异地备份等方案

## 灾备设计最重要的两个指标
### RPO
最多允许丢多少数据？
> Recovery Point Objective
发生灾难以后，我最多可以接受丢失多长时间的数据？

例如：
RPO = 24 小时，意味着：

最坏情况下，可以接受丢失过去 24 小时的数据。

### RTO
恢复时间目标
> Recovery Time Objective

发生故障以后，最多允许业务中断多长时间？

### 这两个指标决定灾备投入
不是所有系统都需要最高等级的灾备。
因为灾备成本与恢复要求通常高度相关。

## 如何设计
### 第一层：本地备份
这是最基础的方案，直接备份在本地服务器上。
优点：
- 成本低
- 恢复速度快
- 建设简单
缺点：
- 如果整个机房发生灾难，本地备份也可能一起丢失。

### 第二层：异地备份
比如备份到：
- 异地机房
- 云存储
即使工厂整个机房损坏，数据仍然保留在异地。

### 第三层：灾备机房
如果企业对业务连续性的要求更高，可以建设灾备机房。
```
             生产机房
           ┌──────────┐
           │ ERP      │
           │ MES      │
           │ WMS      │
           └────┬─────┘
                │
             数据同步
                │
                ↓
           ┌──────────┐
           │ 灾备机房 │
           │ ERP      │
           │ MES      │
           │ WMS      │
           └──────────┘
```
发生故障后，可以切换机房

### 第四层：双活
两套完全在运行的环境。即：

两套 ERP、两套 MES、两套数据库、两套存储、两套网络……

这个成本可能非常高，且真正复杂的地方，并不是“再买一套服务器”，而是：
- 数据同步
- 应用一致性
- 数据库一致性
- 网络切换
- DNS 切换
- 用户切换
- 第三方接口切换
- 消息队列切换
- 文件同步
- 身份认证
- 外部系统回调
- 切换后的业务验证

## 恢复演练
不管用上面的哪个方案。都必须定期进行演练。

并不断改进。

避免真正出问题时，遇到新的，不可控的情况。
