# 钉钉飞书等平台代替OA和HR的可行性
## 背景
源自与一个制造业老板的交流：

钉钉、飞书、企业微信等平台，通常已经具备了，HR系统及OA系统的相关功能，那还有必要上专业的OA, HR的系统吗？直接使用这样的平台作为企业的入口是不是更好？

## 结论

在制造业里，用钉钉这类协同平台替代一部分传统 OA，通常是可行的；但想把它同时完整替代“专业 HR 系统 + OA 系统”，要看企业规模、用工复杂度和生产现场管理深度。

在制造业里，用钉钉这类协同平台替代一部分传统 OA，通常是可行的；但想把它同时完整替代“专业 HR 系统 + OA 系统”，要看企业规模、用工复杂度和生产现场管理深度。
特别是在员工的：
- 复杂排班的情况
- 计件，计时薪资的情况时
会无法满足。

这时还是需要做选择：
- 购买专业系统
- 自己开发相应的功能模块并维护

通常自己开发成本会比较高，除了开发费用，还有服务器，数据库，维护，网络等相关费用。不能只看投了多少时间。
可以先轻后重，后续再考虑买复杂系统。
即：
> 钉钉作为统一的员工入口 + 协同平台 + 基础人事/OA 平台。

而不是传统的：
```
OA系统
+
HR系统
+
考勤系统
+
审批系统
+
低代码平台
+
ERP
```

## 真实的场出发：每天要办的事
对于一家制造业，相关的组织机构树可能是：
```
董事长 / 总经理
        │
────────────────
│       │       │
生产部    销售部    财务部
│
├── 车间主任
│
├── 班组长
│
└── 一线员工
```
员工可能有：
-  办公室人员 
-  销售人员 
-  采购人员 
-  仓库人员 
-  品质人员 
-  设备人员 
-  车间主任 
-  班组长 
-  一线工人 
-  临时工 
-  外包人员

相关的事务可以分为以下几类：
### 第一类：OA办公流程-钉钉非常适合替代
比如：
#### 行政类
```
请假
加班
出差
外出
补卡
调休
会议室
用车
采购申请
办公用品申请
宿舍申请
```

#### 财务类
```
费用报销
借款申请
付款申请
差旅报销
合同付款
预算申请
```

#### 管理类
```
合同审批
印章申请
招聘申请
入职申请
离职申请
岗位调整
转正申请
奖惩申请
制度发布
```

这些流程本质上都是：
> 表单 + 审批 + 通知 + 权限 + 数据记录
这正是钉钉、宜搭这种平台擅长的领域。

### 第二类：基础 HR 管理 —— 钉钉也可以承担很大一部分
制造业的HR基础业务包括：
```
组织架构
部门
岗位
员工档案
入职
转正
调岗
离职
劳动合同
员工通讯录
考勤
请假
加班
假期
培训
绩效
```
这一层实际上钉钉已经覆盖得比较多。
钉钉官方的智能人事目前覆盖人事、考勤、假期、招聘、培训、绩效、OKR、薪酬、人才盘点等模块。

如果业务并不是特别复杂，我认为完全可以先尝试：
```
钉钉
+
智能人事
+
考勤
+
审批
+
宜搭
```

### 第三类：人与生产发生耦合：钉钉无法满足的地方
这里是最关键的地方。
很多人会觉得：HR 系统不就是管理人员、考勤、工资吗？

但制造企业最麻烦的，恰恰就在：**人和生产发生耦合。**

例如一个普通互联网公司：
```
9:00 上班
18:00 下班
工资 = 基本工资 + 绩效
```

但制造业可能是：
```
A车间
三班倒

B车间
两班倒

C车间
常白班

D车间
旺季临时夜班
```

员工还可能：
```
今天在A产线
明天调到B产线
后天请假
周末加班
晚上顶夜班
月底又有调休
```
然后工资又可能：
```
基本工资
+ 加班费
+ 夜班补贴
+ 岗位津贴
+ 绩效
+ 计件工资
+ 品质奖
- 缺勤
- 其他扣款
```
这时候就不好处理了。

### 第四类：小应用场景-可以考虑使用宜搭实现
制造企业里经常存在很多“小需求”
比如：

#### 设备维修申请
```
员工发现设备异常
      ↓
提交故障
      ↓
设备部门接单
      ↓
维修
      ↓
维修完成
      ↓
记录维修历史
```

如果只是：
-  100 台设备 
-  基础维修流程 
-  维修记录 
-  简单统计 
完全可以：
钉钉 + 宜搭

#### 生产异常上报
```
班组长
  ↓
选择：

设备异常
物料异常
品质异常
人员异常
工艺异常

  ↓

提交
  ↓

推送负责人
  ↓

处理
  ↓

关闭
```
这种场景也非常适合低代码。
宜搭也支持流程、表单、报表、API/第三方服务等扩展和集成能力。

## 最终架构-架构图
以钉钉作为统一的入口，然后通过集成的方式，对接各业务主系统。如：
```
                    员工
                      │
                      ▼
                ┌──────────┐
                │   钉钉    │
                │ 统一入口 │
                └────┬─────┘
                     │
        ┌────────────┼────────────┐
        │            │            │
        ▼            ▼            ▼
      OA流程       HR基础        业务应用
        │            │            │
      宜搭/审批     智能人事      宜搭
        │            │            │
        └────────────┼────────────┘
                     │
              ┌──────▼──────┐
              │   集成层     │
              │ API / ETL等 │
              └──────┬──────┘
                     │
      ┌──────────────┼──────────────┐
      ▼              ▼              ▼
     ERP            MES           专业HR
```

员工不要关心：
```
我要去ERP？
我要去HR？
我要去OA？
我要去MES？
```

而是：
我打开钉钉。
然后：
```
我要请假
→ 钉钉

我要看工资
→ 钉钉

我要提交采购申请
→ 钉钉

我要看培训
→ 钉钉

我要提交设备维修申请
→ 钉钉

我要申请生产异常
→ 钉钉
```
后台可能是不同系统。
但员工不需要知道。
