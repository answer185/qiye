# 首屏加载分析

## 业务背景
首屏加载优化是前端性能优化里最常见也是最重要的场景之一。它的原因可能是多样的，通常我们可以将浏览器加载和解析的过程分为多个阶段，然后逐个阶段针对性的去分析。

### 解析流程
- 域名解析和服务器连接请求建立，这个阶段通常不会出问题。
- HTML下载
- JS/CSS下载
- 按顺序执行CSS和JS
- React渲染
- 数据请求完成后渲染。

### 阶段
可以将上面的过程分为：
- 资源加载阶段
- JS执行阶段
- 渲染阶段
- 数据请求阶段
这几个阶段也是常见的性能瓶颈。
如果再有问题，那就是代码架构的问题了。

## 资源加载阶段
这通常是最先检测的阶段，通过chrome的Netword调试框，可以分析出：
- 请求的JS文件是否过大。比如如果bundle的大小有3MB+，则可能构建时没有开启code spliting, 没有拆分vendor， 没有tree-shaking。
- 请求过多：可能没有合并代码，没有开启HTTP2，资源太碎片化了。
- 有没有使用CDN, 开启HTTP2，开启GZIP压缩。
然后针对性解决即可。

## JS执行慢
这个也是常见的瓶颈，其可能原因有：
- 主bundle太大，则解析、编译和执行的时间就会长。
- 有大量的同步代码在执行：比如一个大JSON或一个大列表数据在进行复杂计算或初始化。
- 某些大型库被全量加载：如moment、lodash及富文本编辑器。
解决方式：
- 如果主bundle太大，可以进行关键路径分析，把与首屏沉浸无关的模块懒加载，减少体积。
- 对于大型复杂计算，使用Web Worker异步处理
- 替换掉或懒加载重库，如将moment必为dayjs，lodash引入懒加载。
- 动态加载像编辑器这样的重库

## 渲染慢
### React 渲染慢
常见的场景有：
- 列表数据过长：比如有上千条数据同时渲染。可以通过虚拟列表解决。
- 不必要的重渲染过多：当父组件频繁更新时，相关的组件，就算没变化也会重新渲染。可以通过React.memo、useCallback解决。
- 页面内容繁多，数据复杂，比如订单详情页面，除了订单自身的信息外，通常要关联：客户、送货单、发货单、回款、退货、操作日志等相关的信息。页面接口多，模块区域多。可以通过- skeleton + 分阶段加载，优先保证可视区域的内容展示。

### CSS渲染
使用JS直接操作元素的长宽等，会导致页面的重排（回流）。或者进行复杂的阴影效果渲染。这都会导致浏览器进行大量的计算，从而影响渲染。

### 其他
- 字体请求失败，如在国内直接使用谷歌字体的WEB Font链接。
- 图片大小没有优化，图片没有异步加载。

## 数据请求慢
通常原因有：
- 业务接口慢：这个要后端优化。
- 并行请求过多且使用HTTP1.1: 可以开启http2，适当合并接口、重新编排接口请求的顺序。
- 串行请求：接口逐个请求，导致时间变长。可以适当并行接口。

## 代码架构层问题
### 依赖瀑布
模块互相import，导致加载链条变长。这通常是模块边界不清晰导致。
### 过度CSR
现在有服务端渲染的技术，可以不用把所有的解析都放在客户端。

### 没有区分关键路径
与首屏无关的内容没有异步加载，导致所有的JS都在执行。
